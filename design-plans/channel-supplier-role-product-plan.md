# New API 渠道供应商角色：产品与功能规划

版本：1.4

更新日期：2026 年 11 月 8 日

状态：产品需求规划

本功能让外部渠道供应商使用现有 New API 账号体系，独立管理自己的渠道、维护供货质量并查看自己的运营数据。平台管理员负责供应商准入和全局调度；渠道查看员保留普通用户全部现有权限，额外获得全部渠道非秘密信息的只读权限，不能读取上游渠道 Key 或修改渠道。供应商之间的渠道、日志、统计和筛选选项完全隔离。

本版纳入渠道查看员，以及分渠道 RPM、TPM、每日采购成本限额。供应商可设置自己渠道的三项限额并查看相应每日金额用量；RPM、TPM 未设置时分别表示无对应上限。达到日限额后自动停止该渠道的新调用，次日北京时间 00:00 自动解除该日限额限制。结果长期未知的 TPM 预占采用自动保守结案，核对期限结束后转为估算占用，再保留 60 秒后释放。

## 一 产品定位与确定边界

| 项目 | 确定规则 |
| --- | --- |
| 账号模式 | 一家供应商一个专用账号，复用现有登录、会话和账号安全能力 |
| 供应商隔离 | 只发现、查看和操作自己的渠道；其他供应商及其渠道、请求日志、统计、筛选项均不可见 |
| 渠道与凭据归属 | 一条渠道只有一个所有者；供应商渠道内全部 Key 记录必须属于同一家供应商，不跨供应商共享业务凭据记录 |
| 渠道上线 | 在管理员预先授权的范围内，测试通过自动上线，无人工审核环节 |
| 调度结构 | 平台先选择供应商池，再选择该供应商内部的渠道 |
| 内部优先级 | 作为智能调度偏好，结合健康、延迟和负载决定实际调用 |
| 密钥回看 | 供应商凭据保存后永久只写，保护绑定凭据及其版本；复制、重新绑定或归属变化不能让任何角色回读原文 |
| 供应商消费能力 | 供应商不创建平台 API Key 或个人访问令牌，不承担消费者充值、调用等功能；此限制不适用于渠道查看员 |
| 渠道查看员 | 普通用户全部现有权限 + 全渠道非秘密信息只读权限；本人 API Key/PAT 管理和消费能力保留，不能读取上游渠道 Key 或修改渠道 |
| 渠道限额 | 管理员可设置全部渠道的 RPM、TPM、每日采购成本限额；供应商可设置自己渠道的三项限额；各项独立，未设置或关闭表示不限 |
| 金额可见性 | 供应商可以查看自己渠道的每日采购成本预算、已用、预占和剩余额度；其他财务数据不开放 |
| 日限额周期 | 固定使用 Asia/Shanghai 自然日；达到限额自动停供，次日北京时间 00:00 重新获得当日预算 |
| TPM 异常结案 | 结果长期未知时先核对，期限结束后按原预占转为估算占用并保留 60 秒；不改变任务结果或清零未知采购成本 |
| 登录与供货 | 禁用登录只影响登录和管理访问；供货状态独立控制新流量，午夜不修改这两项状态 |

供应商的每日采购成本预算是首期金额可见性的限定例外，不扩展为客户售价、平台收入、利润、完整财务报表或结算权限。本期不建设账单确认、付款和争议处理。

首期不提供供应商自行注册、多员工账号、消费者与供应商双身份切换、跨供应商渠道直接转让。供应商专用账号不叠加渠道查看员身份。

复用现有采购供应商实体及其 ID，新增账号绑定与渠道所有权。采购统计标签本身不授予登录用户渠道操作权或历史日志查看权。

## 二 角色权限与工作台

### 2.1 权限矩阵

“自己的渠道”以服务器记录的所属供应商为准，包括供应商自行创建，以及管理员明确分配给它的渠道；不能通过名称、标签或前端筛选判断归属。

渠道查看员继承普通用户的全部现有能力，权限矩阵中的渠道限制仅适用于渠道管理资源。本人消费 API Key、个人访问令牌（PAT）、充值、钱包、订阅、模型调用、本人用量和日志、个人设置及账号安全均沿用普通用户规则，包括其既有功能开关、额度和安全校验；不能把查看员账号整体设为只读。

| --- | --- | --- | --- |
| 创建和管理本人消费 API Key/PAT | 不允许 | 保留普通用户全部既有能力 | 沿用既有本人凭据管理规则 |
| 本人模型调用、充值、钱包和订阅 | 不提供消费者能力 | 保留普通用户全部既有能力 | 沿用既有规则 |
| 查看本人消费用量、请求日志及导出 | 不提供消费者能力；供货日志见下方 | 保留普通用户全部既有能力，仅本人数据 | 沿用既有规则 |
| 本人资料、设置及账号安全管理 | 允许按既有规则管理本人账号 | 保留普通用户全部既有能力 | 沿用既有规则 |
| 创建供应商及绑定账号 | 不允许 | 不允许 | 允许 |
| 查看渠道及所属供应商 | 仅自己的渠道和本人供应商资料 | 全部，只读 | 按管理员权限查看 |
| 新建渠道 | 在授权范围内创建 | 不允许 | 允许，并可指定供应商 |

| 调整支持模型 | 在授权范围内，新增模型需测试 | 不允许 | 管理平台准入及模型映射 |

| 恢复渠道 | 仅解除自己的暂停；不能绕过其他限制 | 不允许 | 可解除其管理权限内的停用 |
| 调整供应商内部优先级 | 自己的渠道 | 不允许 | 允许 |
| 调整平台优先级、权重、分组 | 不允许 | 不允许 | 允许 |
| 设置 RPM、TPM、每日采购成本限额 | 自己的渠道 | 不允许 | 全部渠道 |
| 配置采购成本规则及继承模板 | 不允许；可查看本人渠道预算准备状态 | 不因附加角色获得成本规则权限 | 允许，预先配置并维护版本 |

| 查看限额及使用状态 | 自己的渠道，包含每日预算金额 | 全部渠道，只读 | 全部渠道 |
| 查看运营概览和稳定性 | 仅自己的数据 | 全部渠道的运营数据 | 按管理员权限查看 |
| 查看渠道供货日志或跨用户请求日志及导出 | 仅自己渠道的脱敏供货数据 | 不随附加角色自动授予；本人消费日志按上方权限保留 | 按管理员权限查看 |
| 读取上游渠道 Key 及认证凭据 | 不允许 | 全部渠道均不允许 | 供应商凭据及其派生副本永久禁止，超级管理员也不允许；其他未受此保护的凭据沿用既有权限 |

| 禁用供应商登录或暂停供应商整体供货 | 不允许操作平台控制状态；可暂停本人渠道 | 不允许 | 两项独立操作，互不隐式变更 |

供应商可以丢弃未投入使用的草稿。已产生调用的渠道不提供供应商侧物理删除，避免日志和在途任务丢失关联。

### 2.2 供应商工作台

| 页面 | 主要内容与操作 |
| --- | --- |
| 供应商概览 | 渠道状态、调用量、用量、成功率、性能趋势、限额状态、待处理异常 |
| 我的渠道 | 新建、修改、测试、暂停、恢复、内部排序；按本人渠道状态、模型筛选 |
| 渠道详情 | 连接配置、可用模型、凭据状态、测试结果、RPM/TPM/日限额配置及使用情况 |
| 稳定性 | 自己渠道和模型的健康、成功率、延迟、错误趋势；限流与故障分开显示 |
| 使用日志 | 同步调用尝试、异步任务提交与完成结果，支持筛选及脱敏导出 |
| 账号安全 | 密码、MFA、Passkey、会话和自身安全记录 |

供应商工作台不展示充值、钱包、订阅、消费者 API Key、用户管理和系统设置。后端对供应商身份同时禁止对应能力；这些供应商专用限制不适用于渠道查看员。

### 2.3 渠道查看员工作台

该角色由管理员在普通用户身份基础上授予。渠道查看员 = 普通用户全部现有权限 + 全渠道非秘密信息只读权限。普通用户导航、本人 API Key/PAT 管理、模型调用、充值、钱包、订阅、本人用量和日志、个人设置及账号安全全部保留，仅额外增加渠道只读入口，无需切换为专用只读账号。

渠道只读入口允许搜索、筛选和查看全部渠道的名称、类型、脱敏来源地址、所属供应商、模型、分组、优先级、权重、状态、备注、限额配置及已有运行数据。不能新建、编辑、复制、删除、启停渠道，也不能执行渠道排序、测试、模型同步、上游余额刷新、上游凭据刷新或渠道额度重置。渠道页面刷新只读取已有数据，不触发上游操作；前端隐藏渠道写入口，后端拒绝渠道写权限，本人普通用户功能的合法写操作正常可用。

禁止返回的秘密材料限定为上游渠道 Key、上游 Access Token/Refresh Token，以及渠道认证头、URL、代理配置和扩展字段中的上游认证材料。本人消费 API Key 的读取和管理、PAT 的创建和展示、本人登录会话的刷新均遵循普通用户既有规则，不因获得渠道查看权限而受限，也不改变 PAT 等凭据已有的只在创建时展示规则。

本人消费日志、用量及已有导出能力继续保留。其他用户请求日志、客户资料和平台财务报表不随附加角色开放；渠道每日预算及使用金额属于明确授权的只读渠道信息。不能利用全渠道聚合或关联编号反查其他用户的请求明细和正文。

授予或撤销渠道查看权限只增减附加的渠道读取能力，不删除、重置或停用本人 API Key/PAT、余额、订阅、消费记录或账号安全设置。撤销后，账号及其凭据不能继续使用已撤销的渠道查看权限，普通用户能力仍正常有效。

### 2.4 管理员侧功能

新增供应商管理入口，支持创建供应商资料与专用用户、将已有采购供应商绑定到新专用账号、配置允许的渠道模板及模型范围、渠道数量上限、测试限额，以及平台调度策略。管理员预先维护供应商可继承的采购成本规则及版本；供应商设置日限额不授予成本计价配置权限。管理员按协议或模板配置有限的 TPM 异常核对期限，并查看自动结案及迟到校正记录。

“禁用登录”和“暂停供货”分别操作：前者禁止新登录、使现有管理会话和管理访问失效，不停止已获许可的渠道供货；后者停止该供应商的新流量，不禁止账号登录。暂停供货不依赖逐条改写渠道状态，供应商不能通过新增渠道绕过。需要同时限制时分别执行两项操作；午夜恢复不得改变任一状态。

现有渠道列表增加所属供应商列、供应商筛选和供应商详情入口；分别展示平台调度信息、内部优先级、RPM/TPM 限额、日预算状态、预计恢复时间。未明确归属的历史渠道显示“未分配”，不自动当作平台自营，也不自动对外开放。

## 三 渠道生命周期与调度

### 3.1 创建与自动上线

1. 管理员创建供应商和专用账号，设置供货范围及平台调度策略。沿用现有用户创建方式配置初始凭据，增加首次改密要求；初始化完成前只开放账号安全设置。
2. 供应商选择授权渠道模板，填写名称、上游地址、凭据和模型，可同时设置 RPM、TPM 和每日采购成本限额；RPM、TPM 未设置即无对应上限。新渠道继承管理员配置的有效采购成本规则。
3. 系统保存待验证配置，通过服务器发起受限测试，不要求供应商创建平台 API Key。如果申请启用日限额但缺少成本规则，保存为待配置，显示“待管理员配置成本，日限额尚未生效”；补齐规则后才允许发起受该预算保护的测试及正式调用，不静默关闭日限额。
4. 每个新增模型通过对应协议测试后自动获得供货资格；未通过的模型保持不可用。异步模型需确认任务结果，不能仅凭接收成功判断生成能力正常。
5. 上线还须满足平台许可、健康、营业时间和渠道限额条件。通过测试不承诺立即有流量或固定调用量。

### 3.2 配置变更

名称、供应商备注、内部优先级和主动暂停即时生效。连接地址、凭据、影响上游请求的参数和新增模型验证后生效；测试期间使用上一份有效配置，失败时保留原配置。

测试结果绑定配置版本。旧配置的迟到测试成功不能启用新配置，不能覆盖管理员停用、供应商暂停、系统熔断或额度限制。限额配置无需重新测试，按第六节独立生效。

### 3.3 状态和暂停

分别保存登录访问状态、平台供货许可、供应商主动暂停、配置验证、系统健康、营业时间、分钟限流和日限额状态，不用一个启用开关覆盖所有条件。新流量准入要求平台供货许可、渠道启停、配置验证、健康、营业时间及已启用的限额均允许；登录访问状态不参与供货准入判断。恢复登录不自动恢复供货，恢复供货也不自动恢复登录。

- 供应商暂停后停止新请求和新任务提交，已预留但未发送的请求重新检查。
- 已发出的普通 HTTP/SSE 请求允许自然结束。
- 人工停用时，已建立 WebSocket 按现有机制关闭，操作前明确提示；限额触发的处理遵循第六节，不能把打开连接视为后续请求不限额。
- 已提交异步任务保留渠道及凭据版本，继续轮询、回调和结果查询。
- 供应商恢复只能解除自己的暂停；保存配置、换 Key 或调整排序不能清除健康历史和额度使用记录。

### 3.4 两层调度

客户请求先经过平台层选择供应商池，再在池内选择具体渠道。平台优先级、权重、容量由管理员控制；供应商内部优先级只在池内作为智能调度偏好，结合健康、延迟和负载生效。

- 两层优先级均为调度偏好，不承诺严格主备或固定份额。
- 内部优先级、渠道数量不直接进入平台层评分或增加平台权重；真实服务质量变化可以间接改变实际分配。
- 平台层健康统计和冷启动状态绑定稳定供应商身份，不能通过增删渠道重置。
- 渠道 RPM、TPM 和日限额属于调用准入条件；池内所有渠道均不可用时，该池不能继续被选择。
- 首期每个逻辑请求对同一供应商池最多发起一次真实上游尝试；失败后按平台规则选择其他候选，共享既有请求重试总预算。
- 尚未发送时被容量或限额拒绝，可在池内改选其他渠道，不计真实上游重试。
- 固定渠道和会话亲和不能绕过限额；严格绑定无法切换时返回临时不可用，不偷偷改用其他渠道。

仅含历史渠道的模型/分组继续原调度；加入供应商池后，历史未归属渠道各自作为管理员控制的独立候选参与平台层调度，不把所有未归属渠道合成一个大池。

## 四 运营数据与可见性

### 4.1 可见数据

| 数据类别 | 首期内容 |
| --- | --- |
| 供货状态 | 本供应商渠道总数、可用数、暂停数、异常数、限流数和可供模型 |
| 流量 | 上游尝试数、触达请求数、调用趋势、最近调用时间 |
| 用量 | 已知输入、输出、缓存 Token；图片张数、视频秒数等按独立单位展示 |
| 性能 | 平均响应耗时、流式平均首 Token 时间、当前承接速率 |
| 稳定性 | 同步成功率、超时、429、5xx、凭据错误和趋势 |
| 异步任务 | 提交接受率、等待、运行、确认成功、确认失败和结果未知 |
| 限额 | 每渠道 RPM/TPM 上限及占用，日预算、当日已用、预占、剩余和恢复时间 |
| 运维 | 测试失败、凭据失效、公开停用原因、配置生效时间和变更记录 |

概览提供最近 24 小时、7 天、30 天和自定义时间范围，在保留策略内按自己的渠道、模型、调用类型下钻。页面显示统计时区、更新时间和采集覆盖情况。

一般历史概览沿用既有明确标注的统计时区，不把 UTC 日桶改标签当作北京时间。每日预算及其用量曲线固定采用北京时间，与第六节预算账本一致，不能复用 UTC 日桶直接判断是否用尽。

### 4.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 上游尝试数 | 每次实际发送的业务推理请求或任务提交计一次，包括聊天、Embedding、Rerank、语音、图像和视频；轮询、结果下载、SSE 分片不计入 |
| 触达请求数 | 在本供应商范围内对逻辑请求去重，不等同全平台独立请求数 |
| 同步成功率 | 完整有效响应的成功尝试除以可判定成功与失败尝试，不仅凭 HTTP 200 判断 |
| 取消与未知 | 客户取消、本地拒绝、未知结果单列，不混入供应商成功率分母 |
| 任务提交接受率 | 上游明确接受的提交除以有可判定结果的实际提交 |
| 任务成功率 | 上游确认成功除以上游确认成功与失败，同时展示结果未知数量 |
| 延迟 | 同步响应、流式首 Token、任务提交响应、任务完成耗时分别展示 |
| 用量 | 实际、估算、未知分开；未知不填零，不从客户扣费反推 Token |
| 测试流量 | 与生产数据分开，不计生产稳定性主指标；真实上游测试仍受渠道限额约束 |

首期不展示 P95/P99。后续增加可合并的耗时分布后再开放，不能由平均值推算。没有请求显示“暂无流量”或“样本不足”，不能显示 100% 可用。限额导致的本地跳过不计上游失败，不触发健康熔断。

### 4.3 日志白名单

供应商日志仅包含调用时间、自己的渠道、实际上游模型、调用阶段、是否流式、结果、上游状态码、归一错误类别、有效耗时、可信用量及其来源、供应商范围内关联编号和该次上游请求编号。异步任务展示状态及平台观测时间，不展示生成内容。

支持按时间、自己的渠道、模型、状态和关联编号筛选，导出使用同一权限范围和字段白名单。同一请求先后触达 A、B 时，A 只能看到 A 的尝试，不能通过关联编号看到 B 或跨供应商重试链。

### 4.4 禁止向供应商展示

- 其他供应商的名称、渠道、模型分布、流量、错误、排名、凭据、预算或成本。
- 平台总流量、全站成功率、供应商平台份额、全局路由参数及未触达自己的请求。
- 客户用户名、邮箱、IP、用户 ID、API Key 标识、用户分组、充值和订阅信息。
- 客户售价、实际扣费、折扣、平台收入和利润、他人采购价格、完整计费表达式及结算报表。
- Prompt、请求正文、响应正文、生成内容、附件、原始错误正文、请求头、堆栈和内部节点信息。
- Key、可用访问令牌、签名链接、恢复码及可导出的秘密密文。

允许供应商查看的金额仅为自己渠道的日预算及预算消耗明细，不借此开放完整成本配置或客户财务数据。预算明细只包含时间、本人渠道关联编号、成本增减、来源和状态。

平台控制台和管理 API 不额外开放客户内容；实际执行推理的上游仍会收到完成请求所必需的输入。

## 五 数据接口与安全要求

### 5.1 身份 归属与接口

扩展现有供应商实体、用户身份和渠道模型，保存账号绑定、供货状态、授权范围、明确的渠道所有者、创建人、内部优先级、独立控制状态和配置版本。供应商池保存管理员调度参数；调用事实冻结请求发生时的授权归属和版本。

一条渠道只有一个所有者；供应商创建渠道及提交 Key 时由服务器写入该供应商 ID 和实际创建人，管理员代建时必须明确指定归属，创建人不等于所有者。每条上游 Key 业务记录只有一个所有者，一条供应商渠道包含的全部 Key 必须与渠道归属一致；新增、替换、批量导入、复制和重新绑定均验证该约束，不允许跨供应商直接转移凭据记录。

相同 Key 字符串不等于同一条授权记录。不同供应商各自提交时建立独立业务记录，凭据去重和绑定不得跨越所有者范围；不能因为字符串相同而合并权限、修改另一方归属、联动更新另一方配置或回显另一方存在。同一供应商范围内复用仍执行完整绑定校验。存量渠道若包含混合或无法确认归属的凭据，先由管理员拆分、核实或要求重新提交，整理完成前不开放给任何供应商。

新增 `/api/supplier/*` 专属接口，覆盖本人资料、本人渠道、测试、状态、内部排序、限额、概览、稳定性、日志和导出。管理员接口扩展供应商绑定、筛选、供货及平台池配置。查看员沿用普通用户接口与权限，仅增加经核验没有渠道变更副作用的渠道只读入口。

授权按普通用户基础权限与附加渠道读取权限组合，不通过提升为管理员或对整个账号套用只读中间件实现。本人消费 API Key 不因附加角色自动获得管理接口访问能力；PAT 沿用既有可申请范围及安全规则，任何凭据都不能获得超出持有人有效权限的渠道写入或上游秘密读取能力。授予、撤销及权限缓存失效覆盖已有会话和凭据，避免撤销后残留渠道读取权限。

- 从服务器登录身份确定范围，先限制数据，再查询、分页和聚合；所有者由服务器写入。
- 列表、详情、搜索建议、筛选选项、总数、批量、导出和预算接口执行相同范围检查。
- 拒绝越权所有者、平台路由和财务配置字段；批量中存在无权对象则整批拒绝。
- 不存在与无权访问返回一致结果；缓存、请求合并和导出任务包含权限范围及版本，下载再次校验。
- 使用独立字段白名单 DTO，不直接序列化管理员渠道、完整日志或任意扩展字段。
- 写操作使用适当写请求并执行 CSRF 防护；不能用 GET 方法名称判断实际是否只读。

当前部分渠道查询接口会自动刷新上游凭据或推进多 Key 状态，不能直接授予查看员；这不限制查看员通过普通用户接口管理本人的凭据和登录会话。供应商和查看员的渠道权限均不能通过前端隐藏替代服务器授权。

### 5.2 凭据只写不读

供应商渠道凭据仅通过 HTTPS 提交，响应不回传原文；详情仅展示别名、是否配置、状态和更新时间。包括超级管理员在内，查看、复制、导出及测试回包均不能返回这些凭据。

只写保护绑定供应商提交的凭据记录、版本及其派生副本，不依赖渠道当前归属；复制、重新绑定、归属变更或移除供应商标签均不能降低保护。同归属复制可以继续使用受保护凭据。跨供应商或复制为平台自营渠道时仅复制非敏感配置，必须重新提交凭据，不能继承原供应商凭据或凭据绑定；原凭据始终不可回读。对历史复制或迁移已经形成的派生副本，同样保留只写保护；无法确认保护来源的记录须先核实，不能默认转为可读。

数据库保存认证加密密文及密钥版本，主密钥与业务数据库分离。明文仅在必要的服务端调用中短暂使用，不进入日志、审计、错误、前端存储或共享缓存。修改上游目标地址必须重新提交凭据，不把隐藏旧密钥转发到新目标。

新凭据测试成功后供新请求使用；在途任务保持原凭据版本，直至结束或明确紧急停用。平台停用凭据不等于撤销厂商侧密钥。网关仍需通过 HTTPS 使用原始凭据调用上游，不能只存不可逆哈希。

### 5.3 自动上线与账号安全

供应商仅使用管理员授权模板，不默认开放脚本、插件安装、服务器代理、远程模型管理和任意请求改写。上游要求有效 HTTPS；测试、模型发现和正式调用统一检查目标，防止内网、回环、链路本地、云元数据、DNS 重绑定和重定向绕过。

更换凭据、连接地址及管理员变更账号权限复用二次验证；禁用登录和权限变化使旧会话及权限缓存失效，供货状态按独立规则控制。审计记录操作者、对象、动作、时间、结果和安全摘要，不记录秘密。

认证和授权验证依据 [OWASP ASVS 5.0.0](https://asvs.owasp.org/)、[认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)；凭据及目标保护依据[秘密管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)和 [SSRF 防护指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

### 5.4 运营采集与历史

现有按模型/分组的稳定性不能直接用作供应商稳定性。新增渠道和供应商持久观测：同步调用记录真实发送与结束，异步任务记录提交尝试和终态，提交失败也必须保留；本地截止、轮询耗尽和上游确认失败分别记录。

采用持久事件、幂等投影和恢复机制，避免多实例及重复回调重复统计。必备运营采集不依赖全站性能面板开关。使用已有已验证用量事实，不改变消费者收费、结算或退款语义，不要求修改任务插件协议。

只有完成凭据保护和运营观测覆盖的模板才向供应商开放。历史按调用时授权归属快照查询，不根据当前渠道所有者或密钥顺序重新归类；缺少可靠授权快照的历史仅管理员可见。跨供应商更换供货方使用新渠道，旧渠道停止新流量并保留历史。

## 六 分渠道 RPM TPM 与每日采购成本限额

### 6.1 配置范围和权限

每条渠道提供三项独立开关及数值，默认未设置、不限制。RPM 未设置表示无 RPM 上限，TPM 未设置表示无 TPM 上限；新建时留空、编辑时清空数值或关闭对应开关均保存为该项不限，并明确显示“不限”。不存在隐藏的默认渠道上限。启用后 RPM、TPM 必须为正整数，每日金额必须为正的有限十进制数；超出系统安全数值范围的输入直接拒绝，不截断或溢出。不用零值混用“停供”和“不限”；局部更新接口未提交某字段表示保留原值，明确清空才关闭对应限制。

三项独立判断：仅设置 RPM 不会启用 TPM，仅设置 TPM 不会启用 RPM，两项均未设置时不执行渠道分钟限流。未开启 TPM 时，不因缺少输出上界或无法形成 TPM 预占而拒绝请求；已启用的日预算、用户限流、权限及既有计费安全校验仍独立生效。

| 设置 | 单位 | 周期 | 达到限制后的行为 |
| --- | --- | --- | --- |
| RPM | 次上游业务推理请求或任务提交 | 滚动 60 秒 | 暂停接收新调用，窗口释放后自动重新参与调度 |
| TPM | 输入与输出 Token 合计 | 滚动 60 秒及未结算预占 | 暂停接收新调用，额度释放后自动重新参与调度 |
| 每日采购成本限额 | USD，明确标注为平台核算采购成本 | 北京时间自然日 | 当日已用达到限额后自动停供，次日北京时间 00:00 解除该日预算限制 |

管理员可设置全部渠道；供应商可设置、修改或关闭自己渠道的 RPM、TPM 和每日限额。两者编辑同一份配置，以成功保存的最新版本生效，使用版本冲突检查防止覆盖并发修改。查看员只能查看，不能设置、清零或恢复。

三项限制按渠道共享，覆盖该渠道全部模型、Key、客户分组和网关实例，不因多 Key、多节点或多模型获得额外额度。不同渠道分别计数；本期不是供应商总预算或共享上游账户限额。

平台独立的供货禁用、管理访问权限和既有用户限流仍有效；供应商登录是否禁用不决定渠道能否供货。供应商调整渠道限额不能解除管理员供货封禁，也不能抬高平台层调度权重。

### 6.2 RPM 规则

以下准入限制仅在渠道 RPM 已设置并启用时执行；未设置时仅保留观测统计，不分配或扣减 RPM 限流许可。

- 采用滚动 60 秒窗口，不在整分钟统一清零，避免分钟边界双倍突发。
- 实际向上游发送一次业务推理请求或任务提交计一次，覆盖聊天、补全、Embedding、Rerank、语音转写、翻译、合成、图像及视频等接口；上游失败和真实重试同样计入，同一渠道不同接口共享计数。
- 在发送前原子预留许可；本地拒绝、改选或取消且未实际发送时释放许可。
- 任务状态轮询、结果下载和 SSE 分片不计业务 RPM；WebSocket 中每次新业务推理请求计一次，不能按连接数计数。
- RPM 满只形成临时限流，不写成人工停用或健康故障。允许路由选择其他合格渠道；全部候选暂时不可用时返回适当的限流结果及可计算的重试时间，不暴露具体供应商。

### 6.3 TPM 规则

以下 TPM 预占和准入限制仅在渠道 TPM 已设置并启用时执行；未设置时不施加 TPM 上限，不要求仅为 TPM 准入补充输出上限。

- 口径为真实文本 Token 的输入加输出；缓存 Token 按规范化用量语义计入一次，不能因价格倍率重复计算。
- 图片张数、视频秒数、credits 不转换成 Token。无文本 Token 语义的模板显示 TPM“不适用”，仍可使用 RPM 和日金额限额。
- 发送前预占输入估算及有界输出预算。优先使用实际发送参数中的有效输出上限；客户端未传 `max_tokens` 等输出上限时，使用与实际模型及调用配置相符的可信模型或授权模板输出上界。防溢出校验常量不作为正常输出预算，不能为限流放宽计费安全边界，也不能静默缩短用户输出。
- 无生成输出的 Embedding 等接口按协议确认其文本 Token 口径，不为向量或排序结果虚构生成 Token。对需要输出预算却无法确定可信上界的请求，跳过该启用 TPM 的渠道，可选择其他合格渠道；全部候选均不满足时返回可识别的计量配置错误，不按零预占放行，也不伪装成等待窗口释放即可解决的限流。
- 结束后以可信实际用量原子校正。正常执行中的预占保留到完成；已结算用量进入结束时刻起的滚动 60 秒窗口，防止长流式请求因启动窗口到期而完全失去约束。
- 确认调用结束但没有可信最终用量时，采用原预占与已观测可信累计 Token 的较大值作为估算占用，并从结束时刻保留 60 秒；不把未知当零，不丢弃已知更高用量，也不永久保留已结束调用的预占。后续迟到用量沿用第 6.3.1 节的幂等校正规则。
- 已开始的生成允许完成；若实际用量超过预占，记录真实值并阻止后续准入直到窗口释放，不因限额中断已开始的正常输出。

#### 6.3.1 结果未知时自动保守结案

1. 执行节点失联且无法恢复调用状态，或执行截止后仍无法确认结果时，保留预占并进入核对。先检查执行租约、任务记录和上游可查询状态；仍有可信执行进展的请求按正常在途处理，不能仅因请求耗时较长、跨日或进程重启而释放。
2. 异常核对时长独立于业务任务执行超时，首期默认 5 分钟，由管理员按协议或授权模板调整为正的有限时长，不允许设为无限等待。在首次进入结果未知时持久化起点和截止时间；查询失败、不支持上游查询、重复任务或重启均不得重置截止时间。恢复正常执行必须有可信进展证据，不能用重复查询旧状态无限延长；配置变更不改变在途记录的原期限快照。
3. 截止时仍无法确认结果，由系统自动将原预占 Token 转为等量的估算占用；如果已观测到超过原预占的可信累计 Token，同时补计差额，不丢弃已知用量。标记“TPM 已按估算结案，业务结果未知”，从实际执行结案的时刻再保留 60 秒后释放，不回溯到请求发送时刻。多节点、重复恢复和重复回调只允许结案一次，不能重新开始这 60 秒或重复释放。
4. 自动结案只结束 TPM 预占，不把任务判为成功或失败，不中断正常结果查询，不触发客户退款，也不释放或清零未知采购成本。采购侧继续保留预占或原日估算成本，按第 6.4 至 6.6 节处理。估算结案不能承诺未知上游实际用量已被精确还原。
5. 迟到可信用量按请求尝试及结果版本幂等校正。估算占用尚未过期时在原窗口内替换为实际用量，不延长原窗口；已过期时更新历史，实际量高于此前已记用量的未计正差额从校正时刻补计 60 秒，不重计整笔用量。实际量较低时只减少该尝试仍有效的占用，不从当前其他请求的占用扣减，也不返还已过期额度；重复或过时结果不重复补计、覆盖新结果或延长窗口。
6. 记录核对原因、截止时间、估算量、自动结案时间和迟到校正状态。管理员可查看全部，供应商仅能查看自己的脱敏记录，不能手动清空占用或伪造终态；查看员只获得允许的渠道聚合状态，不增加跨用户请求明细权限。

### 6.4 每日金额口径

每日限额按平台记录的渠道采购成本累计，不使用客户实际扣费、累计 used_quota、上游充值额或余额差额替代。沿用现有成本快照语义：调用时冻结的计费基准与有效采购成本配置形成平台核算成本；该金额可能是估算采购成本，不宣称等于厂商最终账单。

首期预算基础币种固定为 USD，与采购成本核算尺度一致；金额输入、已用、预占和剩余均标明 USD。展示币种转换不改变实际预算阈值。按高精度十进制或安全定点数核算，汇总后显示舍入，不累计界面四舍五入值。

- 每次真实上游尝试的成本归实际执行渠道，不能只记录最终成功渠道，也不能把客户计费额直接当采购成本。
- 真实测试和诊断中的业务推理请求纳入渠道预算及适用的 RPM/TPM，但在生产经营统计中仍单独标记，不能通过测试入口绕过限额。新配置通过受控验证通道测试，不以配置已经验证上线为前提；该例外不解除授权、目标校验、所需成本规则和明确禁止上游访问的安全限制。
- 订阅、免费请求或客户零扣费不等于上游成本为零，仍按采购成本累计。
- 上游已发送但结果不明的请求不自动视为零成本；保留对应预占或保守估算，后续可幂等校正。
- 管理员预先配置可继承的采购成本规则，新渠道继承有效版本，每次调用冻结当次成本快照。供应商只能设置日限额，不能修改采购计价规则。申请启用日限额但缺少规则时可以保存待配置草稿，明确显示“待管理员配置成本，日限额尚未生效”，该待配置版本不能上线或以不限额方式承接请求。管理员补齐后，完成预算准备和必要测试再自动生效；无额外人工上线审核。
- 日限额本身仍为可选项，未申请启用时不因缺少成本规则而阻断供货，未知成本不得显示为零。已启用日限额后若某次请求无法形成有效成本预算，该渠道对该次请求不可选，并提示管理员或本人供应商处理；已有预算规则失效时按核算不可用阻止新准入，不能静默降级为不限额。
- 已提交任务的状态轮询和结果取回继续执行，不作为新生成再次预占同一任务预算；平台可核算的额外上游收费仍应归原任务成本，不能重复记账。

### 6.5 并发预占和自动停供

发出新请求前，统一检查渠道权限、可用性及已启用的 RPM、TPM 和日预算，并原子完成所需许可预留。未设置的限额不参与拦截。任一检查失败时释放其他尚未使用的预留，不带着部分许可无限等待。

日预算准入条件为“当日已确认成本 + 尚未结算预占 + 本次成本预算不超过每日限额”。结算后将本次预占幂等转换为实际平台核算成本，释放差额或记录补差。

- 已确认成本达到或超过日限额时，记录独立原因“当日采购成本限额已用尽”，立即停止新的上游调用和任务提交；已经预留但尚未发送的请求再次校验。
- 仅因在途预占使剩余额度不足时，显示“预算预占中”；某次请求预算大于剩余时显示“剩余额度不足以承接本次请求”。二者均不误标为已实际花完，可在预占释放后重新参与调度。
- 已发出的 HTTP/SSE 和已提交异步任务继续完成。WebSocket 上停止接受新的生成请求，在途生成可完成；无法逐次执行限额检查的协议不得开放受限渠道，不能通过复用连接绕过。
- 实际成本超出预估时保留真实超额并停止新增请求，不截断在途输出、不把记账成本钳成限额值。预占降低并发超支风险，但不承诺厂商最终账单绝不超支。
- 已确认的采购侧退款或采购成本纠正才调整原请求所属日期的已用成本；未使用预占只减少待结算预占，不冲减已发生成本。平台向客户退款不改变渠道采购成本或预算，例如采购成本已用 80 USD，客户退款 50 USD 后仍为 80 USD。三类事件分别记录、幂等处理，不能重复冲减或把成本改为负数。
- 已经触发的“当日限额已用尽”当天不因采购侧退款或成本下调自动重新开闸，次日恢复或由有权角色提高/关闭日限额后重新判断；尚未触发耗尽的渠道可按纠正后的已用与预占正常判断剩余额度。

限额必须在服务端、多实例间统一执行，不能依赖异步日志聚合、前端显示或单节点内存计数。某项已启用限额所必需的许可或账本状态不可确定时，暂停依赖该状态的新准入，避免在存储故障或恢复期默认不限额。仅设置 RPM/TPM 的渠道不因未启用的日预算不可核算而停供；未启用 TPM 时不因 TPM 预算未知单独阻断，但仍须满足已启用日预算等独立核算要求。

### 6.6 北京时间零点自动恢复

固定使用 IANA 时区 `Asia/Shanghai`。一个预算日为北京时间当日 00:00（含）至次日 00:00（不含），与服务器时区、浏览器语言和其他统计页面时区无关。

1. 次日 00:00 开始使用新的日期预算账本，当日已用和新请求预占从零开始，上一日记录保留。
2. 自动解除上一日的“日限额已用尽”限制；渠道在其他条件允许时重新参与调度，无需供应商或管理员手动开启。
3. 不解除管理员供货停用、供应商主动暂停、供应商整体停供、健康熔断、配置未验证、预算待配置或营业时间限制；不修改登录访问状态。仅被禁用登录但供货许可有效的渠道，满足其他条件时可以继续供货；RPM/TPM 滚动窗口及异常核对也不因零点额外清零。
4. 使用日期驱动的准入判断，并以后台任务刷新界面和状态；不能只依赖一次零点定时任务。零点停机、任务延迟、重启及多节点重复执行都不能导致不恢复或重复给额度。
5. 请求在实际发送时冻结所属北京时间日期。若预占后尚未发送就跨越零点，须释放旧日未用预占并在新日重新准入，失败则不发送。23:59:59 发出、次日完成的请求及跨日任务仍结算到原日，不能挤占新一天预算，也不能因补记昨日超额重新停用新一天渠道。
6. 恢复记录包含原因、日期和时间。界面展示“北京时间次日 00:00 解除日限额限制”，有其他阻断条件时同时说明，不能承诺一定上线。

示例：渠道设置日限额 100 USD，11 月 8 日北京时间累计达到 100 USD 后停止新调用；11 月 9 日 00:00 开启新的 100 USD 预算。如果管理员仍在停用该渠道，则继续停用。如果 11 月 8 日的在途请求在零点后结算，使昨日实际成本达到 102 USD，记录昨日超额 2 USD，新一天的预算仍为 100 USD。

### 6.7 调整限额和展示

修改限额不清空任何使用记录。提高 RPM/TPM 后按既有窗口重新判断；降低后在窗口占用低于新限额前停止新增。提高日限额超过当日已用及预占，或关闭日限额，可即时解除预算原因的阻断，但不解除其他停用原因。降低至低于已用成本时立即进入日限额耗尽；仅低于已用加预占时阻止新增，等待预占结算。

关闭限额只关闭对应准入限制，成本和适用的请求/Token 占用继续采集。首次启用或重新启用每日金额限额时，纳入当日已发生成本及在途承诺，不能从配置保存时重新计数。若无法还原完整的当日预算账本，明确提示不能当日启用每日金额限额，待核对补齐或下一个完整北京时间预算日再启用；已启用日限额所需账本发生异常时按核算不可用暂停新准入。上述当日成本账本要求不作为启用 RPM/TPM 的条件。

RPM/TPM 未设置或关闭期间，观测数据用于统计及之后启用时的核对，不构成限流许可要求。启用分钟限额时必须能够还原当前窗口及适用在途占用；无法可靠还原时拒绝本次启用并说明原因，保持原配置，不把未知当零。关闭 TPM 后，已有异常记录继续核对和校正，但不再因 TPM 占用阻止准入；其他已启用限制不受影响。

重启、换 Key、重排渠道、改名、手动暂停/恢复均不能重置额度。首期不提供“清空今日用量”按钮。创建独立新渠道有独立预算，页面明确这不是供应商总额度；已使用渠道不能通过删除重建保留原身份却重置账本。

渠道详情增加“限流与每日预算”区域，管理员和该渠道供应商可编辑，查看员为只读。展示 RPM 上限及窗口占用、TPM 上限/已结算占用/预占、日预算/已用/预占/剩余、超额、成本来源、更新时间、北京时间日期和下次日额度恢复时间。未设置的项目显示“不限”，与 TPM“不适用”、计量配置不完整和“待管理员配置成本”分开。TPM 异常核对及估算结案显示对应状态，不能显示为业务任务已经结束。供应商的所有字段、明细和统计都限定本人渠道。

配置变更、日限额触发、午夜解除、人工提高或关闭限额、TPM 异常自动结案及迟到校正均写入审计，记录操作者或系统任务、渠道、前后配置或用量、日期和原因。分钟限流使用汇总状态和计数，避免每次请求产生重复告警。

### 6.8 数据和接口增量

在渠道权限模型内新增限额配置及版本、运行状态投影、分渠道分钟许可计数、按渠道和北京时间日期的日预算账户，以及可幂等关联尝试/任务的预占和成本调整记录。TPM 异常记录持久化核对起止时间、原预占、估算结案状态和迟到校正版本；恢复不能依赖易失缓存 TTL。内部记录不能保存 Key 或客户正文。

供应商侧增加本人渠道限额的读取和更新接口，以及日预算用量明细读取接口；管理员侧支持全部渠道的同类操作，查看员仅有读取能力。状态区分 RPM 限流、TPM 限流、预算预占、日限额耗尽和核算不可用，不能共用人工启停字段。

日预算账本持久化在主库，独立于日志开关、日志保留期及概览异步投影；多实例原子预占、幂等结算、故障恢复和重复事件去重属于上线必需能力。读取接口不触发凭据刷新、测试或额度重置。

## 七 交付与验收

### 7.1 交付顺序

1. 身份与安全基础：供应商及查看员身份、渠道归属、专用权限、凭据只写、审计和存量迁移。
2. 供货管理：管理员与供应商工作台、版本化测试、自动上线、独立状态和两层调度。
3. 渠道限额：RPM/TPM 准入、采购成本预占和结算、北京时间日切、三类角色配置与查看能力。
4. 数据闭环：同步/异步采集、概览、稳定性、脱敏日志、预算明细和导出隔离。
5. 小范围试运行：使用两家测试供应商和一个查看员核验隔离、只读、调度及限额后逐步开放。

正式对外开放前，前四项必须共同完成。P95/P99、多员工账号、供应商总预算、财务结算和外部告警订阅留待后续版本。

### 7.2 功能与隔离验收

| 场景 | 必须达到的结果 |
| --- | --- |
| A 使用渠道、日志、搜索、筛选和导出 | 所有可发现数据仅属于 A，不显示 B 的存在及其数据 |
| A 伪造所有者、平台优先级或混入其他渠道 | 后端拒绝，批量操作不部分生效 |
| 同一渠道使用多个 Key 或批量导入 Key | 渠道只有一个所有者，所有 Key 业务记录与渠道同归属；混入他人凭据时整批拒绝 |
| A、B 分别提交相同 Key 字符串 | 建立独立业务记录，不提示另一方存在，不合并权限或联动修改另一方配置、归属及历史 |
| 存量渠道包含混合或未知归属凭据 | 整理、拆分或重新提交完成前不向供应商开放；不能只修改渠道所有者就通过校验 |
| 同归属复制、重新绑定受保护凭据 | 保护及归属约束继续有效，所有角色均不能从详情、复制响应、导出或测试回包读取原文 |
| 供应商渠道复制为平台自营或其他供应商渠道 | 只复制非敏感配置，目标必须重新提交凭据；超级管理员仍无法回读原供应商 Key，历史派生副本也不降级 |
| 供应商直接请求消费者/管理员接口 | 无法创建 API Key/PAT、消费、充值或获得管理员权限 |
| 普通用户获得渠道查看权限 | 保留全部普通用户能力，仅新增全渠道非秘密信息只读入口及权限，不获得管理员能力 |
| 查看员创建和管理本人消费 API Key/PAT | 创建、读取和管理按普通用户既有规则执行；不新增 PAT 回看能力，不自动扩大消费 Key 的接口范围 |
| 查看员执行普通用户自助操作 | 模型调用、充值、钱包、订阅、本人资料修改及账号安全操作与普通用户一致，不被渠道只读限制阻断 |
| 查看员查询本人消费日志和用量 | 本人日志、用量和已有导出能力正常；不能查询其他用户请求或借渠道聚合反查他人明细 |
| 查看员访问所有渠道 | 可以读取允许字段，不能获得任何上游渠道 Key、上游令牌或渠道认证材料 |
| 查看员调用渠道写接口或有副作用的渠道 GET | 拒绝渠道新建、编辑、复制、删除、启停、排序、测试、模型同步、上游余额/凭据刷新、渠道限额修改及重置；本人普通用户写操作仍可用 |
| 撤销渠道查看权限 | 恢复普通用户渠道可见范围，原本人 Key/PAT、余额、订阅、消费记录及安全设置保持有效；既有会话和凭据不能继续访问撤销的渠道读取能力 |
| 需验证的配置变更及迟到测试结果 | 仅对应有效版本的测试结果可以生效，不覆盖人工停用或限额状态；限额配置无需渠道测试，按第六节独立生效 |
| 内部排序及大量新增渠道 | 不直接提高供应商池权重，不改变其他供应商的平台配置 |
| SSE 中断、任务提交失败、重复回调 | 分类正确，不漏失败提交，不重复调用或用量记录 |
| 禁用登录但供货许可仍有效 | 新登录及原管理会话不可用，渠道满足其他条件时继续供货；午夜不恢复登录 |
| 暂停整体供货但登录仍开启 | 仍可登录和查看本人数据，新渠道或新配置不能绕过停供；午夜不恢复供货许可 |
| 多实例、缓存和存量迁移 | 权限、状态和历史归属一致，未分配渠道不自动对外开放 |

### 7.3 限额验收

| 场景 | 必须达到的结果 |
| --- | --- |
| 供应商设置 RPM、TPM、每日限额 | 三项均可编辑，仅本人渠道；能查看本人每日预算金额 |
| RPM、TPM 均未设置，或仅设置其中一项 | 未设置项显示“不限”且不施加上限；仅启用项执行准入，不隐式启用另一项 |
| 清空限额、关闭开关及局部接口更新 | 明确清空或关闭只取消对应限制；局部请求未提交的字段保留原值；零值不被误认成停供或不限 |
| TPM 未设置且请求没有输出上限 | 不因 TPM 预算不可估算而拒绝；仍执行已启用的 RPM、日预算及既有安全校验 |
| 只启用 RPM，采购成本未知但 RPM 计数可靠 | 按 RPM 及其他有效准入条件正常承接，不因未启用的日预算未知而停供 |
| 查看员请求限额更新或清零 | 服务器拒绝，状态与用量不变 |
| 同渠道多模型、多 Key、多节点并发 | 共用一份限额，最后一份许可或余额不会被重复发放 |
| 同渠道混用 chat、Embedding、Rerank 和语音等接口 | 所有实际业务请求共享 RPM，失败和真实重试计入，轮询、下载及流式分片不计入 |
| 滚动分钟边界及失败重试 | 不出现整分钟双倍突发；真实失败尝试计 RPM，未发送不计 |
| 已启用 TPM 但请求未传 max_tokens | 使用与实际配置一致的可信模型或模板输出上界；不能用防溢出常量替代，也不静默缩短输出 |
| 已启用 TPM 且无法确定所需输出上界 | 该渠道不承接此请求，可改选合格渠道；无可用候选时明确计量配置原因，不按零放行或提示无效的窗口重试 |
| 长流式和缺少可信 Token 用量 | 预占持续有效，结束后校正，未知不作为零；输出不因额度不足被无故截断 |
| 调用正常结束但没有最终 usage | 采用原预占与可信累计 Token 的较大值作为估算占用，结束 60 秒后释放；不丢弃已知更高用量或永久限流 |
| 失联或执行截止后终态长期未知 | 进入有截止时间的核对，期限结束自动按原预占保守结案，已知更高用量补差，再保留 60 秒释放；任务结果及未知采购成本不变 |
| 核对期间重启、无上游查询接口或重复执行恢复任务 | 原截止时间保留，只结案一次；不重置估算窗口、不重复释放，业务执行超时关闭也不能导致核对无限等待 |
| 正常长任务仍有可信执行进展 | 不因超过异常核对默认时长、跨日或重复读取旧状态而提前结案；只有进入结果未知状态才启动核对期限 |
| 估算窗口内和过期后的迟到用量 | 窗口内校正原占用且不续期；过期后的未计正差额补计 60 秒，负差额不抵扣其他请求；重复及过时结果不重复记账 |
| 图片、视频和 credits | 不伪装成 Token，TPM 不适用时明确标注；RPM/金额限额仍有效 |
| 供应商创建渠道并申请日限额，但缺少成本规则 | 保存待配置并提示管理员补齐，不能显示预算生效或静默按不限额上线；供应商不能自行修改采购计价 |
| 管理员补齐成本规则，或未申请日限额 | 前者完成预算准备及必要测试后自动生效；后者可按其他条件上线，不因日预算准备要求被额外阻断 |
| 已启用日限额，成本未知、客户免费或订阅请求 | 未知成本不按零放行；客户零扣费不绕过采购成本预算 |
| 并发日预算预占与结算 | 预占不足阻止新增；达到实际日限额自动停供；重复事件不重复扣记 |
| 已用采购成本 80 USD，平台向客户退款 50 USD | 已用采购成本仍为 80 USD，不额外释放 50 USD 预算 |
| 采购侧退款、成本纠正与未使用预占释放 | 前两项校正原日已用，后一项只减少对应预占，幂等且不记负成本；已触发的日耗尽不自动解除 |
| 日预算 100 USD 达到或超过阈值 | 立即停止新调用，记录真实超额，不修改人工启停状态 |
| 北京时间 23:59:59 至 00:00 | 新日期获得新预算，仅清除前一日预算限制，不重置 RPM/TPM |
| 零点前已预占但零点后才发送 | 释放原日未使用预占，成功申请新日预算后才发送 |
| 午夜停机、重启或多个恢复任务 | 请求时能正确识别新日期，无漏恢复或重复增加预算 |
| 跨日请求、任务、采购侧退款和迟到费用 | 采购成本始终回写原日，历史调整不挤占或重新封锁新日预算；迟到 Token 按 TPM 独立规则处理 |
| 日限额与管理员停用/主动暂停同时存在 | 零点后仍遵守其他阻断条件，不能误开启 |
| 提高/降低/关闭限额及换 Key | 重新判断资格但不清空用量；并发修改有版本冲突保护 |
| 当日首次启用或关闭后重新启用每日金额限额 | 包含此前当日采购成本和在途承诺，不完整账本不能按全新额度启用；不把此条件套用到 RPM/TPM |
| 开启分钟限额时占用无法还原，或关闭已有 TPM | 前者拒绝本次开启并保留原配置，不能按零占用启用；后者停止 TPM 拦截但保留观测及异常核对，其他限制仍生效 |
| 测试、固定渠道、亲和和 WebSocket 新生成 | 不能绕过准入；预算限制不阻止已提交任务的结果查询 |
| 已启用限额所需存储或账本状态不可确定 | 停止依赖该状态的新准入，恢复后幂等修复，不降级成无限额；未启用项目的状态缺失不单独阻断 |

数据库变更须在真实 SQLite、MySQL 和 PostgreSQL 验证新建、代表性旧版本升级及重复启动幂等；共享日志路径受影响时覆盖 ClickHouse。交付记录实际版本、命令和结果。账务及数量计算遵守 `.agents/rules/billing.md`，不能因限额功能削弱现有预扣、结算、退款和溢出防护。

前端复用现有业务组件，全部文案支持七种语言，普通数字和金额复用项目格式化工具。测试使用可控时钟验证分钟和北京时间日切边界，不依赖等待到真实零点或长时间 sleep。
